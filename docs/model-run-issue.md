# Проверка AI-интеграции: один план и сравнение

Владелец: Егор. Ветка разработки: `agent/ai-integration`. Новый код этой ветки **проверен двумя живыми вызовами OpenAI на `gpt-5.6-sol`** 23 сентября 2026 года. Результаты приведены ниже. Историческая проверка прежнего кода на другой модели сохранена отдельно в [model-verification.md](model-verification.md); NVIDIA в текущем прогоне не проверялась.

## Что делает интеграция

Числа рассчитывает `src/simulator.py`. Модель получает готовые результаты и выбирает ID проверенных фактов для разделов «Сильные стороны», «Риски», «Компромиссы». Приложение проверяет выбранные ID и само формирует текст; модель не задаёт Score или отображаемые числа. При отсутствии настроек, ошибке API или некорректном ответе возвращается честный `source=computed_facts`.

Для запуска нужен Python 3.10+. Основной сценарий и OpenAI используют стандартную библиотеку; дополнительный NVIDIA-адаптер требует `python3 -m pip install -r requirements-model.txt`. После интеграции актуального `main` сетевой timeout — 20 секунд для OpenAI и 45 секунд для NVIDIA, автоматических повторов нет. Интерфейс ждёт ответ расчётного API до 75 секунд. Это ограничения ожидания, не гарантия полного времени команды. Фактическое время каждого сценария выводится в `latency_ms`.

Команда выбрала OpenAI Responses API. OpenAI-запрос задаёт JSON Schema, ответ дополнительно проверяется локально; механизм описан в [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Дополнительный адаптер NVIDIA использует OpenAI SDK (`openai==3.16.2`) с `base_url=https://integrate.api.nvidia.com/v1` и Chat Completions; его живой прогон не требуется для выбранного OpenAI-сценария.

Команды выполнять из корня **того worktree, который проверяется**:


```sh
read -rs "OPENAI_API_KEY?OpenAI API key: "
echo

```

`gpt-5.6-sol` — модель, указанная пользователем в локальной конфигурации и проверенная в этой ветке. Доступ определяется аккаунтом; модель по умолчанию в коде не задана. Для этого точного ID запрос использует `reasoning.effort=none` и лимит 512 выходных токенов: задача состоит в коротком выборе ID фактов. Поддержка режима описана в [официальном руководстве GPT-5.6](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6). Для других ID параметр reasoning не добавляется.

Если позже понадобится дополнительный провайдер NVIDIA, настройка аналогична; точный доступный ID выбирается в его кабинете:

```sh
read -rs "NVIDIA_API_KEY?NVIDIA API key: "
echo
export NVIDIA_API_KEY
export NVIDIA_MODEL="<точный доступный ID модели>"
```

Альтернатива — создать в редакторе `.env` в корне этого worktree и заполнить только нужную пару. Не заменяйте существующий `.env` копированием шаблона.

```dotenv

NVIDIA_MODEL=
```

```sh

```

Модуль `explanation.py` читает `.env` только своего worktree, не родительского репозитория и не текущего каталога shell. Переменная окружения имеет приоритет, включая пустое значение. Ключ не включать в commit, чат, отчёт или командную строку. Не копировать `.env` между worktree. При `--provider auto` полная настройка NVIDIA имеет приоритет; OpenAI выбирается, если NVIDIA не настроен полностью. При `--provider nvidia` или `--provider openai` другой провайдер отключён на время проверки. Ошибка выбранного провайдера не запускает второй платный запрос.

## Проверка без сети

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check-model.py --provider openai --check-config
```

`--check-config` выводит только `provider`, `model`, `configured`, `reason`. Код 0 означает полную локальную настройку; код 2 — отсутствие полной пары ключ/модель. Наличие настройки не подтверждает действительность ключа, доступность модели или успешный AI-вызов.

Для принудительной проверки резервного режима даже при существующем `.env`:

```sh
NVIDIA_API_KEY= NVIDIA_MODEL= OPENAI_API_KEY= OPENAI_MODEL= python3 scripts/check-model.py --scenario both
```

Ожидается код 2 и `source=computed_facts`, `reason=model_not_configured` в обоих результатах. Сеть не используется.

## Реальные вызовы

Один контрольный вызов OpenAI:

```sh
python3 scripts/check-model.py --provider openai --scenario single
```

Один вызов для сравнения:

```sh
python3 scripts/check-model.py --provider openai --scenario comparison
```

Оба сценария одной командой — всего два запроса, без повторов:

```sh
python3 scripts/check-model.py --provider openai --scenario both
```

Дополнительная проверка NVIDIA использует `--provider nvidia` и отдельно настроенную пару его переменных. Старый вызов `python3 scripts/check-model.py` сохранён: один план, автоматический выбор настроенного провайдера. Для выбранного командой пути используйте явный `--provider openai`. Не выполняйте все примеры подряд: `both` заменяет два отдельных запуска.

## Контроль результата

| Сценарий | Вход | Ожидаемый результат расчёта |
| --- | --- | --- |
| `single` | M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка | Базовый Score `52.55768`, итоговый `56.54307`, стоимость `95` |
| `comparison` | Тот же план и замена M5/Сарыарка → M3/Нура | Score `56.54307 → 57.20556`, стоимость `95 → 100` |

Каждый результат содержит `source`, `provider`, `model`, `reason`, безопасные `error_code`/`error_type`/`http_status`, контрольные числа, `latency_ms`, `checked_at_utc` и проверенный текст. `both` возвращает объект с массивом `results` в порядке `single`, `comparison`. Тела ошибок API, заголовки, ключи и текст исключений не выводятся.

`error_code` уточняет причину резервного режима: `authentication` — ключ или доступ; `rate_limited` — лимит провайдера; `timeout` — истекло ожидание; `invalid_model_output` — ответ не прошёл проверку; `provider_error` — другая ошибка провайдера; `network_error` — сетевой сбой. Эти причины не меняют рассчитанный Score и не запускают автоматический повтор.

В режиме живой проверки код 0 означает, что **все** запрошенные сценарии дали `source=model` от выбранного провайдера. Код 2 означает резервный режим или несовпадение провайдера; такой результат не подтверждает AI-вызов. Отсутствие числового изменения модели обязательно: контрольные расчёты выполняются до запроса.
