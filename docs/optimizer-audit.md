и исходном ТЗ/датасете из `task/`. Это аудит конкретной
ветки; новые коммиты `main` требуют повторной сквозной проверки после
интеграции. Проверка официального сайта организатора через браузерный
инструмент в этом сеансе не удалась, поэтому организационные правила ниже
основаны на сохранённых командой документах `AGENTS.md` и `docs/submission.md`.

Команды проверки:

```bash
python3 -m unittest discover -s tests -v
python3 benchmark/optimizer_benchmark.py --self-test
python3 benchmark/optimizer_benchmark.py --scenario official --oracle --optimizer python3 src/optimizer.py
python3 benchmark/optimizer_benchmark.py --scenario seeded_jitter --oracle --optimizer python3 src/optimizer.py
python3 benchmark/optimizer_benchmark.py --scenario critical_boundary --oracle --optimizer python3 src/optimizer.py
python3 benchmark/optimizer_benchmark.py --scenario saturation --oracle --optimizer python3 src/optimizer.py
```

Критический следующий шаг: владелец NVIDIA-доступа подтверждает реальные
модельные вызовы для одного плана и сравнения с явным ID модели и результатом `source: model`.
В текущем окружении нет настроенного ключа или ID модели; успешный мок не
свидетельствует о доступности внешнего API. После интеграции ветки команда
повторно проверяет кнопку, README и точные значения на сдаваемом commit.
