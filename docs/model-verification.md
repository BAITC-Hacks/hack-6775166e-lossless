При первом сравнительном вызове модель обернула JSON в Markdown-блок, поэтому прежний строгий парсер вернул честный `source=computed_facts`. Парсер расширен: он удаляет только целиком охватывающий JSON блок Markdown, затем проверяет структуру и каждый ID факта по вычисленному списку. Повторный живой вызов прошёл. `python3 -m unittest discover -s tests -q` завершился успешно: 22 теста, включая такой формат ответа и запрет выдуманного ID.

## Вопрос советнику

23 сентября 2026 года из ветки `agent/human-advisor` выполнен живой вызов `python3 scripts/check-model-advice.py` через OpenAI Responses API, модель `gpt-4o-mini`. Ключ был прочитан из игнорируемого `.env`; в рабочем worktree временная копия файла имела права `0600`. Проверка завершилась с кодом 0 и `source=model`. Для контрольного плана получены Score `56.54307`, `57.20556` и `57.236735`. На вопрос «Почему замена улучшает Score, но ухудшает Сарыарку?» ответ явно сообщил, что оба альтернативных варианта снижают балл Сарыарки, и показал проверенные районные значения `56,30`, `55,09`, `55,77`.

Первый вызов вернул `source=computed_facts`: модель указала порядковые номера вместо строковых ID фактов. После уточнения формата в запросе и отбора релевантных вычисленных фактов повторный живой вызов прошёл. Контрольный тест дополнительно требует показывать факты названного человеком района, даже если модель выбрала лишь общие факты. Числа во всех вариантах остаются результатом симулятора; текст модели не выводится напрямую.

Модель выбирает значимые факты, а не рассчитывает Score и не пишет отображаемые числа. Для сдаваемой версии нужно повторить запуск после интеграции и обеспечить разрешённый правилами путь проверки AI без личного ключа участника.
