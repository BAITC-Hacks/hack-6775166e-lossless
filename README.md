# Аким на 5 часов

Рабочий AI-симулятор пяти бюджетных решений для пяти условных районов Астаны. Пользователь получает одинаковые исходные показатели и бюджет **100**, выбирает ровно пять разных мероприятий M1–M14 и видит рассчитанные изменения районов, итоговый **Astana Quality of Life Score**, диаграммы и объяснение последствий.

## Запуск

Нужен **Python 3.10+** и современный браузер. Приложение использует только стандартную библиотеку Python; `pip install` и сетевой доступ для основного сценария не нужны. Проверено локально на Python 3.14.6.
Текущий движок и веб-интерфейс — проверенный локально прототип. Команда отдельно принимает финальную версию перед сдачей.

```bash
git clone https://github.com/BAITC-Hacks/hack-6775166e-lossless.git
cd hack-6775166e-lossless
python3 src/server.py
```

Откройте **http://127.0.0.1:8000/**. Для другого порта: `PORT=8080 python3 src/server.py`. Сервер доступен только на `127.0.0.1`; для локальной проверки учётная запись не нужна. Остановить — `Ctrl+C`.

Настройки описаны в `.env.example`; приложение читает переменные окружения, но не загружает `.env` автоматически. Для фактического AI-объяснения предпочтителен ключ Егора: `NVIDIA_API_KEY` и точный ID доступной ему модели в `NVIDIA_MODEL`. Используется официальный [NVIDIA API Catalog](https://docs.api.nvidia.com/nim/re/reference/llm-apis), endpoint `/v1/chat/completions`. Если NVIDIA не настроена, доступны необязательные `OPENAI_API_KEY` и `OPENAI_MODEL` через [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text). Модель получает полный проверенный расчёт: дельты районов и показателей, вклад каждой меры, синергии и Score; для совета по одной замене — оба расчёта. Она выбирает ID только из фактов, построенных симулятором, для разделов «сильные стороны», «риски» и «компромиссы». Версию задаёт значение `NVIDIA_MODEL` либо `OPENAI_MODEL`; она должна быть доступна аккаунту с ключом. Таймаут ответа — 8 секунд. Результат модели не меняет Score и не добавляет собственные числа. При отсутствии ключа или сбое API приложение явно показывает объяснение из вычисленных фактов и помечает, что AI-модель недоступна. Для проверки основного сценария эксперту личный ключ участника не нужен. Реальный вызов платной модели в этой версии **пока не подтверждён**.

Проверочные вызовы после настройки ключа и модели: `python3 scripts/check-model.py` для одного плана и `python3 scripts/check-model-comparison.py` для сравнения двух планов. Скрипты не выводят ключ; успех означает `source: model` и выбранный провайдер, а при `source: computed_facts` они завершаются с кодом 2: модельный вызов не подтверждён. Перед прогоном владелец аккаунта проверяет доступность модели, цену и остаток лимита.

## Проверка через интерфейс

1. Откройте приложение: исходный Score **52,56**, бюджет **100**, каталог содержит 14 мер в пяти направлениях.
2. Выберите M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка. Нажмите «Рассчитать сценарий». Стоимость **95**, итоговый Score **56,54** (внутреннее значение `56.54307`), показаны районные изменения, диаграммы и синергия M10 + M12.
3. Нажмите «Найти лучшую замену одного решения». Приложение сравнит исходный план с лучшим допустимым соседним планом: M5/Сарыарка → M3/Нура, стоимость **100**, Score **57,20556**, прирост **0,66249**. Модель может выбрать значимые факты из обоих расчётов; ручной план изменится только после нажатия «Применить замену».
4. Не применяя замену, нажмите «Сравнить с рекомендацией». Точный оптимизатор переберёт допустимые наборы и покажет рядом ваш план и M2/город, M3/Нура, M8/Нура, M9/Нура, M14/город: стоимость **98**, Score **57,236735** (на экране 57,24). Таблица показывает баллы всех районов и разницу между планами, включая район, которому ваш вариант полезнее. Ручные слоты сохраняются; «Применить рекомендацию» меняет их только по явному нажатию. Первый запрос занимает около 4 секунд на компьютере команды, следующие используют кэш сервера.
5. Повторите M8 в другом слоте и рассчитайте снова: увидите причину отказа, итогового Score и диаграмм для невалидного набора нет.

Сервер проверяет ровно пять уникальных мер, максимум две меры каждого направления, район для районной меры, отсутствие района для городской, бюджет и конфликты. Эффекты учитывают лаг, синергии и ограничение 0–100. Score вычисляется по формуле датасета после всех изменений; остаток бюджета бонуса не даёт, порядок мер не влияет на результат.

## Автоматические проверки

```bash
python3 -m unittest discover -s tests -v
python3 benchmark/optimizer_benchmark.py --self-test
python3 benchmark/optimizer_benchmark.py --scenario official --oracle
python3 benchmark/optimizer_benchmark.py --scenario official --oracle --optimizer python3 src/optimizer.py
python3 benchmark/london_ward_benchmark.py --oracle --optimizer python3 src/optimizer.py > /tmp/london-result.json
```

Тесты проверяют исходный Score **52.55768**, контрольный Score **56.54307**, ошибки валидации, синергии, независимость от порядка и границы объяснения. Benchmark использует отдельную реализацию формулы и точный перебор; на официальных данных максимум по модели — **57.236735** среди **694395** допустимых портфелей. Независимый оптимизатор `src/optimizer.py` совпал с oracle на официальном и трёх синтетических сценариях: `regret = 0`, около 4 секунд против около 12 секунд у oracle на компьютере команды. Случайный поиск с тем же бюджетом времени тоже нашёл максимум в этих четырёх случаях, поэтому подтверждённое преимущество оптимизатора — гарантия точного ответа, а не более высокий Score. В `docs/benchmark-data.md` описаны воспроизводимые стресс-сценарии с seed `20260923` и условия сравнения. Синтетика не заменяет официальные пять районов в приложении.

## Ограничения и происхождение

Числа, эффекты мер и формула взяты из двух исходных DOCX в `task/`; датасет задачи синтетический. Это симуляция по заданной модели, а не прогноз реальных социальных последствий. Лицензия на публикацию DOCX отдельно не указана; репозиторий команды приватный. Отдельный benchmark использует официальный открытый CSV London Ward Profiles по лицензии OGL v2: исходные строки, SHA, нормировка и ограничения описаны в `docs/benchmark-data.md`. На пяти лондонских ward оптимизатор совпал с независимым oracle (`regret = 0`), но показатели там служат техническими proxy, а эффекты мер остаются искусственными. В официальный Score Астаны лондонские данные не подставляются. Источники NYC и OECD пока каталогизированы, данные из них не включены.

Рантайм и интерфейс написаны для этой задачи на стандартных Python, HTML, CSS и JavaScript без сторонних библиотек. До старта задачи в репозитории существовали инфраструктурные скрипты и рабочие инструкции; их роль описана в `docs/parallel-agents.md`. Код из исследовательского репозитория `gentle_precision` в приложение не переносился.
