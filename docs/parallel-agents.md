# Параллельная работа в Codex

## Запуск

1. Интегратор фиксирует выбранное ТЗ и разбивает обязательные пункты на независимые части с владельцем, файлами и проверкой каждой части. Основную функциональность начинаем только после официального старта.
2. Для каждой независимой части открой отдельную задачу Codex в этом проекте. В новой задаче выбери **Worktree** и общую исходную ветку с актуальными инструкциями. Попроси агента выполнить только назначенный пункт, проверить его и сообщить commit, изменённые файлы и команду проверки.
3. Один агент остаётся интегратором в основном checkout: собирает изменения, запускает сквозную проверку буквально по README и отвечает за итоговую отправку в командный репозиторий.

Пример задания агенту после распределения пунктов ТЗ:

> Реализуй пункт [точная цитата/ссылка на ТЗ] в своём worktree. Твоя зона файлов: [пути]. Согласуй интерфейс с интегратором до правки общих файлов. Проверь результат командой [команда] и сообщи наблюдаемый результат, commit и ограничения. Не изменяй чужие зоны и не отправляй итоговую версию вместо интегратора.

## Сборка результата

- В каждом worktree создай собственную ветку `codex/<часть>`, сделай содержательный commit и передай интегратору имя ветки или commit. Не используй одну ветку в двух worktree одновременно.
- Общие файлы, прежде всего `README.md`, манифесты зависимостей и конфигурацию запуска, меняет интегратор после согласования интерфейсов. Если агенту нужно их изменить, сначала сообщи интегратору конкретную правку.
- Интегратор переносит готовые commits в основную ветку, разрешает конфликты, проверяет матрицу ТЗ и чистый запуск. Перед часовым контрольным сроком отправляет реальный результат и сверяет удалённый commit.
- Локальный `AGENTS.md` намеренно игнорируется Git. `.worktreeinclude` копирует его в новые управляемые Codex worktree с этого компьютера. При работе другого участника или в обычном Git worktree передай ему актуальные инструкции отдельно; сведения для эксперта внеси в сдаваемый README.

Пока ТЗ недоступно, не назначай агентам реализацию несуществующих пунктов. Можно параллельно читать ТЗ, проверять окружение и готовить план, не создавая основную функциональность до объявления старта.
