# Сдача решения «Аким на 5 часов»

Основание: [снимок формы «Сдать решение»](../task/submission-form-2026-09-23.png) для спец-трека Astana Innovations, предоставленный командой 23 сентября 2026 года и сохранённый без изменений. Это снимок состояния интерфейса, а не подтверждение отправленной заявки. Форма и ТЗ имеют разные роли: DOCX описывают функции симулятора, форма определяет видимые поля и порядок финальной отправки.

## Что показывает форма

| Элемент | Наблюдение |
| --- | --- |
| Трек и кейс | «Спец-трек Astana Innovations», «Аким на 5 часов» — AI-симулятор управления городом. |
| Дедлайн | 23 сентября, 18:00. Часовой пояс в форме не виден; рабочий ориентир команды по положению — 18:00 по времени Астаны. |
| Репозиторий | Платформа создала приватный `https://github.com/BAITC-Hacks/hack-6775166e-lossless`; на снимке указаны два приглашённых участника. |
| Название проекта | Поле для ввода. Финальное название согласовать с командой. |
| Теги / технологии | Поле для тегов; ввод через Enter или запятую, максимум 10. Указывать только технологии, реально использованные в отправленной версии. |
| Описание проекта | Поле для текста о продукте и проблеме; первые 300 символов показываются в списке решений. Описывать только работающие функции. |
| Действие | Кнопка «Сдать решение». Снимок не показывает, какие из полей обязательны и можно ли менять заявку после отправки. |
| Доступ после дедлайна | По тексту формы push блокируется, репозиторий становится read-only. Права на код остаются у команды; организатор получает доступ для проверки. |

## Контрольный порядок

1. Интегратор проверяет требования ТЗ, сборку и один сквозной сценарий из чистого состояния по финальному README. Зафиксировать фактические команды и результат.
2. Убедиться, что финальные исходники, README, данные и необходимые файлы уже в командном репозитории, без ключей и закрытых данных. Сделать содержательный commit и push **до 18:00**.
3. Сверить локальный commit с удалённой веткой и убедиться, что доступ к репозиторию для проверки есть. Если нужен определённый branch/ref, уточнить его через официальный канал: на снимке форма его не указывает.
4. Согласовать название проекта, не более 10 фактических тегов и короткое описание. Первые 300 символов описания должны сами объяснять пользу и работающий результат.
5. Заполнить поля формы и нажать «Сдать решение» до дедлайна. Проверить появившееся подтверждение или статус отправки; сам снимок их не показывает.

**Внутренний запас времени:** закончить push и сверку удалённого commit до 17:45, оставить время на форму и сбои доступа. Это рекомендация команды, а не отдельный срок организатора. После 18:00 рассчитывать на исправление репозитория нельзя: форма предупреждает о блокировке push.

## Что ещё проверить

- Часовой пояс дедлайна в интерфейсе не указан; при расхождении с положением спросить организатора.
- Форма не показывает обязательность полей, лимит длины полного описания, возможность редактирования после отправки и требуемую ветку. Не принимать предположения об этих правилах за факт.
- Название, теги и описание пока не заполнены: их нужно готовить по финальной работающей версии, чтобы заявка, код и README совпадали.
