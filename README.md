# Аким на 5 часов

Командный репозиторий решения задачи HackAlem AI 2026: AI-симулятор управления условными районами Астаны. Пользователь получает единый виртуальный бюджет, выбирает ровно пять городских мероприятий и видит их влияние на показатели районов и итоговый **Astana Quality of Life Score**.

## Статус

Сейчас в репозитории находятся ТЗ, синтетический датасет и рабочая документация. Приложение, команда запуска и тесты **ещё не реализованы**. По мере разработки этот раздел будет заменён проверенными командами для запуска именно сдаваемой версии.

Ключевые ограничения: бюджет 100 условных единиц для всех команд, ровно пять уникальных мероприятий, не более двух из одного направления, обязательный выбор района для районных мер, запрет несовместимых сочетаний и запрет превышения бюджета. Недопустимый набор не получает Score: валидатор должен объяснить причину.

Числовой результат задаётся формулой из датасета: эффекты мероприятий учитывают лаг, затем применяются синергии и ограничение показателей диапазоном 0–100; Score учитывает среднее по населению, слабейший район и показатели ниже 40. AI объясняет вычисленный результат и компромиссы, но не подменяет детерминированный расчёт числами собственного сочинения.

## Проверочный сценарий после реализации

1. Открыть приложение и убедиться, что начальный бюджет равен 100, а исходный Score по датасету равен **52,56** после округления до двух знаков.
2. Выбрать M7 для Нуры, M8 для Нуры, M10 для Нуры, M12 для города и M5 для Сарыарки. Стоимость набора — **95**; он допустим и активирует синергию M10 + M12. Контрольный расчёт по формуле даёт Score **56,54307** (на экране 56,54), что согласуется с указанным в датасете ориентиром ≈ 56,5.
3. Попробовать набор дороже 100, повтор мероприятия, конфликтующую пару и шестое решение. Система должна отклонить каждый случай с понятной причиной и без расчёта Score.
4. Изменить допустимый набор: показатели районов и итоговый Score должны измениться, а AI-объяснение должно опираться на фактически вычисленные дельты.

Эти шаги описывают будущую проверку, а не выполненные тесты текущего репозитория. Требования к среде, установка, переменные окружения, точные команды запуска и фактические результаты проверок будут добавлены вместе с приложением.
